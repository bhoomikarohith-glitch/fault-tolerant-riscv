# Next-PC Logic Specification

**Project:** Fault-Tolerant RV32I RISC-V Processor  
**Module:** Next-PC Logic  
**RTL File:** `rtl/core/next_pc.sv`  
**Specification File:** `docs/specs/next_pc.md`  
**Status:** Design Specification

## 1. Purpose

The Next-PC Logic computes the address of the next instruction to fetch. It also produces two values used elsewhere in the datapath:

- `pcplus4`, the return address written to `rd` by JAL and JALR.
- `pctarget`, the PC-relative target used by branches and JAL, and the result of AUIPC.

The module is purely combinational. The PC itself is stored in the PC Register.

## 2. Functional Requirements

The module shall:

1. Compute PC + 4.
2. Compute PC + extended immediate.
3. Select the next PC for sequential execution, taken branches, JAL and JALR.
4. Clear bit 0 of the JALR target.
5. Apply a fixed priority when more than one control input is asserted.
6. Drive `pcplus4` and `pctarget` at all times, whichever value is selected.

The module shall not compare register values, add the JALR base and offset, or store the PC.

## 3. Interface Specification

| Signal | Direction | Width | Description |
|---|---|---|---|
| `pc` | Input | 32 bits | Current PC from the PC Register |
| `immext` | Input | 32 bits | Extended immediate from the Immediate Generator |
| `aluresult` | Input | 32 bits | ALU result; holds `rs1` + immediate for JALR |
| `branch` | Input | 1 bit | Current instruction is a conditional branch |
| `jump` | Input | 1 bit | Current instruction is JAL |
| `jalr` | Input | 1 bit | Current instruction is JALR |
| `branchtaken` | Input | 1 bit | Branch condition result from the Branch Comparator |
| `pcnext` | Output | 32 bits | Address of the next instruction |
| `pcplus4` | Output | 32 bits | PC + 4 |
| `pctarget` | Output | 32 bits | PC + `immext` |

### Interface Notes

- `branch`, `jump` and `jalr` are generated by the main decoder.
- The module does not require a clock or reset input.

## 4. Address Calculations

- `pcplus4` = `pc` + 4
- `pctarget` = `pc` + `immext`

Both additions wrap modulo 2^32.

`immext` is already in the correct format for the instruction: B-type for branches, J-type for JAL, U-type for AUIPC. Its least significant bit is zero for branches and JAL.

## 5. Next-PC Selection

| Priority | Condition | `pcnext` |
|---|---|---|
| 1 (highest) | `jalr` = 1 | `{aluresult[31:1], 1'b0}` |
| 2 | `jump` = 1 | `pctarget` |
| 3 | `branch` = 1 and `branchtaken` = 1 | `pctarget` |
| 4 | Otherwise | `pcplus4` |

- `branchtaken` shall be ignored unless `branch` = 1.
- The main decoder should assert at most one of `branch`, `jump` and `jalr`. The priority order guarantees deterministic behavior if more than one is asserted.

## 6. JALR Target

The JALR target is (`rs1` + immediate) with bit 0 cleared.

- The addition is performed by the ALU: the main decoder selects the immediate as operand B and sets `aluop` = `00` (ADD).
- This module only clears bit 0 of `aluresult`.
- Bit 1 is not cleared. A target with bit 1 set is misaligned; exceptions for misaligned instruction addresses are outside the scope of this processor.

**Design decision:** The reference design uses a 1-bit `PCSrc`, computed in the controller as (Branch AND Zero) OR Jump, and supports only BEQ and JAL. This implementation adds JALR, and moves the PC-source decision into this module, so all next-PC logic lives in one place.

## 7. Requirements on Other Modules

- **Main decoder:** shall output separate `branch`, `jump` (JAL only) and `jalr` signals. It does not compute `PCSrc` or use an ALU Zero flag. For JALR it shall select the immediate as ALU operand B and set `aluop` = `00`.
- **Result (write-back) multiplexer:** shall select `pcplus4` for JAL and JALR, and `pctarget` for AUIPC.

## 8. Combinational Behavior

The module shall implement combinational logic only. Every path shall assign `pcnext`, so that no latch is inferred.

The reference adder and multiplexer building blocks may be reused inside this module.

## 9. Integration Requirements

Inputs:

- `pc` from the PC Register.
- `immext` from the Immediate Generator.
- `aluresult` from the ALU.
- `branch`, `jump` and `jalr` from the main decoder.
- `branchtaken` from the Branch Comparator.

Outputs:

- `pcnext` to the PC Register.
- `pcplus4` and `pctarget` to the result multiplexer.

## 10. Verification Requirements

The unit testbench shall verify the following.

### Sequential Execution

- With no control input asserted, `pcnext` = `pc` + 4.
- `branchtaken` = 1 with `branch` = 0 still gives `pc` + 4.

### Branches

- Taken branch with a positive offset.
- Taken branch with a negative offset (a backward loop).
- Not-taken branch gives `pc` + 4.

### Jumps

- JAL gives `pctarget` for positive and negative offsets.
- JALR with an odd `aluresult` gives the value with bit 0 cleared.
- JALR with an even `aluresult` gives the value unchanged.

### Priority

- `jalr` overrides `jump` and `branch`.
- `jump` overrides `branch`.

### Outputs

- `pcplus4` and `pctarget` are correct whichever value is selected.
- Wraparound: `pc` = `0xFFFF_FFFC` gives `pcplus4` = 0.

## 11. Completion Criteria

The module is considered complete when:

- [ ] PC + 4 and PC + immediate are computed correctly.
- [ ] All four next-PC cases are selected correctly.
- [ ] The JALR target has bit 0 cleared.
- [ ] The priority order matches this specification.
- [ ] `pcplus4` and `pctarget` are always driven.
- [ ] No latches are inferred.
- [ ] The implementation passes its unit testbench.
- [ ] The module integrates correctly with the PC Register, main decoder, ALU and result multiplexer.
