# Immediate Generator Specification

**Project:** Fault-Tolerant RV32I RISC-V Processor  
**Module:** Immediate Generator  
**RTL File:** `rtl/core/immediate_gen.sv`  
**Specification File:** `docs/specs/immediate_gen.md`  
**Status:** Design Specification

## 1. Purpose

The Immediate Generator extracts the immediate field encoded within a 32-bit RISC-V instruction, rearranges the relevant instruction bits according to the instruction format, and extends the result to 32 bits.

The output is supplied to the processor's execution datapath for operations such as:

- Arithmetic with immediate operands
- Load and store address calculation
- Conditional branch target calculation
- Jump target calculation
- Loading upper immediate values

The module is purely combinational.

## 2. Functional Requirements

The module shall:

1. Accept a 32-bit instruction.
2. Accept a control signal identifying the immediate format.
3. Extract and rearrange the appropriate instruction bits.
4. Perform sign extension where required.
5. Insert the required constant zeros for branch, jump, and upper immediates.
6. Produce a 32-bit immediate output.
7. Produce a deterministic zero output for unsupported immediate-format selections.

The module shall not decode the complete instruction or determine whether the instruction is legal. Those responsibilities belong to the decoder and control unit.

## 3. Interface Specification

| Signal | Direction | Width | Description |
|---|---|---|---|
| `instr` | Input | 32 bits | Complete 32-bit instruction |
| `immsrc` | Input | 3 bits | Selects the immediate format |
| `immext` | Output | 32 bits | Extended immediate value |

### Interface Notes

- `instr` contains the complete instruction, including bits `[31:0]`.
- `immsrc` is generated by the processor's decoder/control logic.
- `immext` is the immediate value supplied to the execution datapath.
- The module does not require a clock or reset input.

## 4. Immediate Format Selection

The `immsrc` signal shall use the following encoding:

| `immsrc` | Format | Typical instructions |
|---|---|---|
| `3'b000` | I-type | ADDI, loads, JALR |
| `3'b001` | S-type | SB, SH, SW |
| `3'b010` | B-type | BEQ, BNE, BLT, BGE, BLTU, BGEU |
| `3'b011` | U-type | LUI, AUIPC |
| `3'b100` | J-type | JAL |
| Other values | Invalid selection | Output zero |

**Design decision:** The reference example uses a 2-bit selector because it handles only four formats. Our implementation uses a 3-bit selector to support all five immediate formats.

## 5. I-Type Immediate

### Purpose

Used by instructions such as:

- ADDI
- SLTI
- SLTIU
- ANDI
- ORI
- XORI
- Load instructions
- JALR

### Source Bits

The 12-bit immediate is extracted from:

`instr[31:20]`

### Required Operation

The 12-bit immediate shall be sign-extended to 32 bits using `instr[31]` as the sign bit.

Conceptually:

`immext = sign_extend(instr[31:20])`

### Requirements

- Output width: 32 bits.
- Sign bit: `instr[31]`.
- The original 12-bit immediate must remain unchanged in the lower 12 output bits.

## 6. S-Type Immediate

### Purpose

Used by store instructions:

- SB
- SH
- SW

### Source Bits

The immediate is split between two instruction fields:

- `instr[31:25]`
- `instr[11:7]`

These fields must be combined in the correct order.

### Required Operation

Construct the 12-bit immediate as:

`{instr[31:25], instr[11:7]}`

Then sign-extend it to 32 bits.

### Requirements

- Output width: 32 bits.
- Sign bit: `instr[31]`.
- The immediate must be reconstructed from both instruction fields.
- The register fields must not accidentally be included in the immediate.

## 7. B-Type Immediate

### Purpose

Used by conditional branch instructions:

- BEQ
- BNE
- BLT
- BGE
- BLTU
- BGEU

### Source Bits

The branch immediate is distributed across:

- `instr[31]`
- `instr[7]`
- `instr[30:25]`
- `instr[11:8]`

### Required Operation

The reconstructed immediate must follow this bit mapping:

| Immediate bit | Source |
|---|---|
| `imm[12]` | `instr[31]` |
| `imm[11]` | `instr[7]` |
| `imm[10:5]` | `instr[30:25]` |
| `imm[4:1]` | `instr[11:8]` |
| `imm[0]` | Constant zero |

The 13-bit branch offset shall be sign-extended to 32 bits.

### Requirements

- Output width: 32 bits.
- Sign bit: `instr[31]`.
- The least significant bit must always be zero.
- The immediate must be reconstructed using the specified bit mapping.

The branch offset is added to the current PC by the processor's next-PC logic, not by the Immediate Generator itself.

## 8. U-Type Immediate

### Purpose

Used by:

- LUI
- AUIPC

### Source Bits

The upper 20 bits come from:

`instr[31:12]`

### Required Operation

The 20-bit field must occupy output bits `[31:12]`, with the lower 12 bits set to zero.

Conceptually:

`immext = {instr[31:12], 12'b0}`

### Requirements

- Output width: 32 bits.
- `immext[31:12]` must equal `instr[31:12]`.
- `immext[11:0]` must always be zero.
- The U-type immediate must not be sign-extended from bit 31 of the instruction in the same way as an I-type immediate.

## 9. J-Type Immediate

### Purpose

Used by the JAL instruction.

### Source Bits

The jump immediate is distributed across:

- `instr[31]`
- `instr[19:12]`
- `instr[20]`
- `instr[30:21]`

### Required Operation

The reconstructed immediate must follow this bit mapping:

| Immediate bit | Source |
|---|---|
| `imm[20]` | `instr[31]` |
| `imm[19:12]` | `instr[19:12]` |
| `imm[11]` | `instr[20]` |
| `imm[10:1]` | `instr[30:21]` |
| `imm[0]` | Constant zero |

The 21-bit jump offset shall be sign-extended to 32 bits.

### Requirements

- Output width: 32 bits.
- Sign bit: `instr[31]`.
- The least significant bit must always be zero.
- The immediate must be reconstructed using the specified bit mapping.

The jump offset is added to the current PC by the processor's next-PC logic.

## 10. Combinational Behavior

The module shall implement combinational logic.

Whenever `instr` or `immsrc` changes, `immext` shall update after the combinational logic settles.

The module shall not:

- Store the previous instruction.
- Require a clock edge to update the output.
- Maintain internal architectural state.
- Calculate branch or jump target addresses.

## 11. Invalid Format Selection

If `immsrc` does not correspond to a supported format, `immext` shall be assigned zero.

This prevents unintended latch inference and provides deterministic behavior for unsupported selector values.

The decoder remains responsible for identifying illegal instructions.

## 12. Integration Requirements

The Immediate Generator shall connect to the instruction and control paths of the CPU.

Inputs:

- Instruction bits from the fetched instruction.
- Immediate-format selection from the decoder/control unit.

Output:

- Extended immediate to the execution datapath.

The output may be selected as an ALU operand or used in branch/jump address calculations, depending on the instruction.

The Immediate Generator itself shall not select the ALU operand or decide whether a branch is taken.

## 13. Verification Requirements

The unit testbench shall verify the following.

### I-Type

- Positive immediate.
- Negative immediate.
- Maximum positive 12-bit immediate.
- Minimum negative 12-bit immediate.
- Zero immediate.

### S-Type

- Correct reconstruction of both immediate fields.
- Positive immediate.
- Negative immediate.
- Zero immediate.

### B-Type

- Correct placement of `instr[7]` into `imm[11]`.
- Correct placement of `instr[31]` into `imm[12]`.
- Least significant output bit is zero.
- Positive and negative offsets.
- Correct sign extension.

### U-Type

- Upper 20-bit field is preserved.
- Lower 12 bits are always zero.
- Zero and nonzero immediate fields.

### J-Type

- Correct reconstruction of all immediate fields.
- Least significant output bit is zero.
- Positive and negative offsets.
- Correct sign extension.

### Invalid Selection

- Unsupported `immsrc` values produce zero.

## 14. Completion Criteria

The module is considered complete when:

- [ ] All five immediate formats are supported.
- [ ] The selector encodings match this specification.
- [ ] All immediate fields are reconstructed correctly.
- [ ] Sign extension is correct.
- [ ] B-type and J-type offsets have a zero least significant bit.
- [ ] U-type lower 12 bits are zero.
- [ ] Invalid selections produce zero.
- [ ] The implementation passes its unit testbench.
- [ ] The module integrates correctly with the decoder and CPU datapath.
